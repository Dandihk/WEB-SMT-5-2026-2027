## Langkah Kerja Praktikum

Tugas dikerjakan dalam bentuk file Markdown baru dengan nama file: **`4.1_Tugas_Perancangan_[NamaKelompok].md`** dan **`5.1_Tugas_Desain_[NamaKelompok].md`**.

### TAHAP 1: Membuat Dokumen Kebutuhan Produk (PRD) Sederhana
Susun dokumen PRD untuk aplikasi kelompok Anda dengan format berikut:
- **Nama Produk/Aplikasi**: Nama web yang akan dikembangkan.
- **Product Overview**: Deskripsi singkat mengenai apa aplikasi tersebut dan solusi apa yang ditawarkan.
- **Objectives**: Tujuan utama pembuatan aplikasi (minimal 2 tujuan).
- **User Persona**: Deskripsi target pengguna aplikasi (siapa saja yang akan menggunakannya).

---

### TAHAP 2: Menentukan Kebutuhan Sistem (Requirements)
Definisikan spesifikasi kebutuhan aplikasi Anda:
1. **Functional Requirements**: Tuliskan **minimal 5 fitur** yang harus bisa dilakukan oleh sistem (contoh: *User dapat melakukan checkout barang*, *Admin dapat menambah data barang*).
2. **Non-Functional Requirements**: Tuliskan **minimal 3 batasan teknis/kualitas sistem** (contoh: *Aplikasi harus responsive di mobile*, *Waktu loading data harus kurang dari 2 detik*).

---

### TAHAP 3: Merancang User Flow & Sitemap
Visualisasikan navigasi dan logika aplikasi Anda:
1. **User Flow**: Gambarkan alur kerja (logika) untuk **satu fitur utama** (misal: Alur Pendaftaran Akun Baru atau Alur Pembayaran/Peminjaman). Anda dapat menggambarnya menggunakan diagram **Mermaid** atau menyusun langkah-langkah logika secara tekstual terstruktur.
2. **Sitemap**: Tuliskan hirarki menu dan halaman website kelompok Anda dalam bentuk diagram pohon (*tree list*) mulai dari Homepage hingga halaman terdalam.

---

### TAHAP 4: Menentukan Arsitektur & Perancangan Database
Dalam pengembangan ini, kita sepakat menggunakan **Arsitektur Client-Server / Decoupled (Modern)** (Frontend terpisah dari Backend API).

1. Tuliskan alasan mengapa pendekatan arsitektur ini baik digunakan untuk aplikasi kelompok Anda.
2. Buatlah **minimal 2 rancangan skema tabel database** yang saling berelasi (contoh tabel `users` dan `transactions` atau `products`). Tuliskan rancangan tersebut dalam format tabel Markdown seperti di bawah ini:

**Contoh Format Tabel Database:**
*Tabel: nama_tabel*
| Nama Kolom | Tipe Data | Keterangan |
| :--- | :--- | :--- |
| `id` | INT | Primary Key, Auto Increment |
| `nama_kolom` | VARCHAR(100) | ... |

---

### TAHAP 5: Perancangan API Endpoint
Rancanglah dokumentasi **RESTful API** yang akan menghubungkan Frontend dengan database melalui Backend. Buatlah **minimal 3 API endpoints** dalam format tabel berikut:

| HTTP Method | URL Endpoint | Deskripsi Fungsi | Request Body (JSON) / Keterangan |
| :---: | :--- | :--- | :--- |
| **GET** | `/api/...` | ... | - |
| **POST** | `/api/...` | ... | `{ "key": "value" }` |
| **DELETE** | `/api/...` | ... | - |

---

### TAHAP 6: Merancang Dokumen Design System (design.md)
Susunlah dokumen panduan desain visual (**`5.1_Tugas_Desain_[NamaKelompok].md`**) yang mencakup 8 elemen utama:
1. **Overview (Brand & Style)**: Tentukan identitas produk, *tone & mood*, serta tema desain visual yang dipilih.
2. **Colors**: Definisikan palet warna (Primary, Secondary, Neutrals, Semantics) lengkap dengan kode HEX dan deklarasi variabel CSS (`:root`).
3. **Typography**: Tentukan *font-family* (Headings & Body) serta tabel hierarki ukuran teks (H1 - Small Text).
4. **Layout & Spacing**: Definisikan sistem grid (desktop/mobile) dan skala jarak (8px Grid System).
5. **Elevation & Depth**: Tentukan tingkatan elevasi/bayangan (*shadow scale*) untuk hirarki visual elemen.
6. **Shapes**: Definisikan skala kelengkungan sudut (*border-radius scale*).
7. **Components**: Dokumentasikan spesifikasi komponen UI utama (misal: Button, Card, Input) beserta kondisinya (*default, hover, focus, disabled*).
8. **Do's and Don'ts**: Tuliskan panduan praktik terbaik (DO) dan hal yang harus dihindari (DON'T) saat membangun tampilan antarmuka aplikasi.
