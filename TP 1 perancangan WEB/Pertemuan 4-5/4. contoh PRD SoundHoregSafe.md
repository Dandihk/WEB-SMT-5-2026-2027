## SoundHoregSafe — Peta Titik Event Sound Horeg Kabupaten Pati

## 1. Latar Belakang

Di Kabupaten Pati, event "sound horeg" (sound system dengan volume sangat besar yang biasa dipakai pada acara arak-arakan, hajatan, atau konvoi) sering digelar di lingkungan permukiman. Suara yang dihasilkan bisa mencapai level yang berbahaya bagi pendengaran, terutama untuk anak kecil dan balita yang sistem pendengarannya masih rentan.

Saat ini tidak ada informasi terpusat yang memberi tahu warga:
- Di mana saja titik event sound horeg sedang atau akan berlangsung
- Seberapa jauh jarak aman yang harus dijaga dari sumber suara tersebut

Akibatnya, orang tua/wali sering tidak siap dan anak-anak terpapar suara keras secara tiba-tiba.

## 2. Tujuan Produk

1. Memberikan informasi real-time/terkini tentang lokasi event sound horeg di wilayah Kabupaten Pati.
2. Menampilkan radius/zona jarak aman di sekitar titik event agar warga (khususnya yang membawa anak kecil/balita) bisa menghindar atau menjaga jarak.
3. Meningkatkan kesadaran masyarakat tentang risiko paparan suara keras terhadap anak-anak.

## 3. Target Pengguna

| Persona | Kebutuhan |
|---|---|
| Orang tua/wali dengan balita | Tahu titik event terdekat & jarak aman sebelum bepergian |
| Warga umum Kabupaten Pati | Info lokasi event agar bisa merencanakan rute |
| Panitia/pelapor event | Bisa melaporkan/menandai lokasi event sound horeg |
| Admin/moderator | Verifikasi & kelola data laporan agar tetap akurat |

## 4. Lingkup (Scope)

### 4.1 Termasuk dalam MVP
- Peta interaktif wilayah Kabupaten Pati dengan titik-titik event sound horeg
- Form pelaporan/input event baru (lokasi, waktu mulai-selesai, estimasi tingkat kebisingan/skala sound)
- Perhitungan & visualisasi zona jarak aman (radius) berdasarkan estimasi level kebisingan
- Filter event: sedang berlangsung, akan datang, sudah selesai
- Notifikasi/peringatan visual saat pengguna mengecek lokasi tertentu yang masuk zona tidak aman
- Panel admin sederhana untuk moderasi laporan (approve/reject)

### 4.2 Tidak termasuk MVP (Future Scope)
- Notifikasi push real-time ke HP
- Integrasi sensor desibel IoT aktual
- Aplikasi mobile native (Android/iOS)
- Sistem akun/login publik (MVP bisa anonim + admin login)

## 5. Alur Pengguna Utama (User Flow)

1. **Pengguna umum membuka web** → melihat peta Kabupaten Pati dengan pin titik event aktif.
2. **Klik salah satu pin** → muncul detail: nama/lokasi event, waktu, estimasi radius aman, status (berlangsung/akan datang).
3. **Pengguna memasukkan lokasi mereka** (opsional: input alamat atau gunakan GPS) → sistem menampilkan apakah lokasi tersebut berada dalam zona tidak aman.
4. **Pelapor** mengisi form "Lapor Event Sound" → mengisi titik lokasi (klik di peta / GPS), estimasi skala sound, waktu.
5. **Admin** login ke panel admin → memverifikasi laporan sebelum tampil publik (untuk mencegah data spam/hoax).

## 7. Kebutuhan Non-Fungsional

- **Performa:** Peta harus memuat < 3 detik untuk data hingga ratusan titik.
- **Skalabilitas:** API backend harus mampu handle beberapa ratus request bersamaan (event viral bisa ramai diakses).
- **Keamanan:** Validasi input untuk mencegah spam/laporan palsu; rate limiting pada endpoint pelaporan.
- **Aksesibilitas:** Desain responsif (mobile-first, karena mayoritas warga akan akses via HP).
- **Ketersediaan:** Uptime minimal 99% (hosting sederhana untuk MVP).

## 8. Logika Zona Jarak Aman (Contoh Perhitungan)

Karena tidak ada sensor desibel aktual di MVP, gunakan pendekatan estimasi berbasis kategori skala sound yang diinput pelaporan/admin:

| Skala Sound | Estimasi dB Sumber | Radius Zona Bahaya | Radius Zona Waspada |
|---|---|---|---|
| Kecil | ~90–100 dB | 50 m | 100 m |
| Sedang | ~100–115 dB | 150 m | 300 m |
| Besar (horeg) | ~115–130+ dB | 300 m | 600 m |

> Catatan: Angka di atas adalah *contoh pendekatan* untuk kebutuhan produk, bukan hasil pengukuran akustik ilmiah. Disarankan berkonsultasi dengan pihak terkait (mis. Dinas Kesehatan/ahli akustik) untuk kalibrasi radius yang lebih akurat sebelum go-live.

Rumus dasar peluruhan suara (opsional untuk versi lanjutan, hukum inverse-square):
```
Lp2 = Lp1 - 20 * log10(d2 / d1)
```
di mana `Lp1` adalah level suara pada jarak referensi `d1`, dan `Lp2` adalah level suara pada jarak `d2`. Ini bisa dipakai untuk membuat radius lebih dinamis di iterasi berikutnya.

## 9. Arsitektur Teknis

### 9.1 Stack
- **Frontend:** Vue 3 (Composition API) + Vite, library peta: Leaflet.js (open-source, gratis) atau Mapbox GL JS
- **Backend/API:** Laravel (REST API), sebagai perantara antara frontend dan Supabase, sekaligus tempat logika bisnis (perhitungan radius, validasi, moderasi)
- **Database:** Supabase (PostgreSQL) — bisa juga memanfaatkan PostGIS extension dari Supabase untuk query geospasial (jarak antar titik)
- **Autentikasi Admin:** Laravel Sanctum (token based) untuk panel admin
- **Hosting:** Frontend bisa di Vercel/Netlify, Backend Laravel di VPS/Railway/Render

## 10. Metrik Keberhasilan (Success Metrics)

- Jumlah laporan event yang masuk per minggu
- Jumlah pengguna unik yang mengakses web saat ada event aktif
- Waktu rata-rata verifikasi laporan oleh admin (target < 30 menit saat event mendekati waktu mulai)
- Feedback kualitatif dari warga (survei sederhana/kolom komentar)

## 11. Risiko & Mitigasi

| Risiko | Mitigasi |
|---|---|
| Laporan palsu/spam | Moderasi admin sebelum tampil publik + rate limit per IP |
| Estimasi radius tidak akurat secara ilmiah | Beri disclaimer jelas di UI bahwa radius adalah estimasi, bukan pengukuran presisi |
| Data event terlambat diinput (real-time gap) | Dorong partisipasi komunitas/RT-RW untuk lapor cepat, sediakan form yang sangat simpel |
| Rendahnya awareness warga soal web ini | Rencana sosialisasi lewat medsos lokal, grup WA RT/RW, atau kerja sama dengan pemerintah desa |

## 12. Roadmap Bertahap

**Fase 1 — MVP (4–6 minggu)**
- Peta dasar + input laporan + radius statis per skala
- Panel admin sederhana

**Fase 2**
- Deteksi lokasi user otomatis (geolocation) + notifikasi visual zona bahaya
- Statistik per kecamatan

**Fase 3**
- Push notification
- Kalibrasi radius dengan rumus akustik lebih presisi / kerja sama pihak berwenang setempat
