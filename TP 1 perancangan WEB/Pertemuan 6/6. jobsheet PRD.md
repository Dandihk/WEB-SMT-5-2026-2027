##  Tujuan Praktikum

Setelah menyelesaikan job sheet ini, peserta didik mampu:
1. Menyusun dokumen **Product Requirements Document (PRD)** yang terstruktur menggunakan 6 langkah panduan Figma.
2. Menguraikan inisiatif produk menjadi **Epics**, **User Stories** (format *As a... I want to... so that...*), dan **Tasks**.
3. Mengelompokkan prioritas fitur menggunakan kriteria **MoSCoW** (Must, Should, Could, Won't Have).
4. Menentukan kriteria rilis (*Release Criteria / MVP*) secara jelas untuk menghindari *scope creep*.

##  Tugas Praktikum

Buatlah file dokumen PRD kelompok Anda dengan nama file: **`6_PRD_[NamaKelompok].md`**. Susun dokumen tersebut dengan mengisi 6 bagian utama berikut sesuai dengan 6 langkah Figma:

### 1. Lay the Groundwork (Fondasi Proyek)
- **Nama Aplikasi / Proyek Web:**
- **Elevator Pitch:** *(Jelaskan aplikasi Anda dalam 1-2 kalimat singkat)*
- **Susunan Tim:**
  - Product Owner / Manager:
  - UI/UX Designer:
  - Developer Frontend/Backend:
  - Tester / QA:
- **Jadwal Peluncuran (Target Rilis MVP):**
- **Potensi Risiko:** *(Sebutkan minimal 2 kendala teknis atau operasional yang mungkin dihadapi)*

### 2. User Persona (Profil Target Pengguna)
- **Nama Persona Utama:**
- **Peran / Profesi:**
- **Kebutuhan Pengguna:**
- **Masalah / Kendala Utama (*Pain Points*):**

### 3. Contextualize Strategic Goals (Tujuan Strategis & Dampak)
- Apa alasan utama membuat web ini?
- Nilai tambah / manfaat terbesar apa yang akan didapatkan oleh pengguna setelah web ini rilis?

### 4. Feature Requirements & User Stories (Spesifikasi Fitur)
Tuliskan **minimal 4 fitur utama** aplikasi kelompok Anda ke dalam tabel berikut dengan format **User Story**:

| ID Fitur | Nama Fitur | User Story (*As a [user], I want to [action] so that [benefit]*) | Prioritas (Must / Should / Could) |
| :--- | :--- | :--- | :--- |
| F-01 | | As a..., I want to... so that... | Must |
| F-02 | | As a..., I want to... so that... | Must |
| F-03 | | As a..., I want to... so that... | Should |
| F-04 | | As a..., I want to... so that... | Could |

### 5. Release Criteria & Scope MVP (Kriteria Rilis Versi Awalan)
- **Fitur WAJIB ada di Versi MVP (Must Have):**
- **Fitur yang DITUNDA ke Versi Berikutnya (Won't Have in MVP):**
- **Kriteria Kualitas (Performa & Tampilan):** *(Misal: loading < 3 detik, tampilan responsif HP & Laptop)*

### 6. Review & Revision Notes (Catatan Review Tim)
- Tuliskan 1-2 pertanyaan atau masukan dari teman kelompok / guru saat meninjau dokumen ini, serta solusi perbaikannya.
